# Domain docs

Before exploring an area, read `GLOSSARY.md` at the repo root and any ADRs in `docs/adr/` that touch it. If they don't exist yet, carry on: `/domain-modeling` creates them when the first term or decision is agreed.

- Name domain concepts with the glossary's terms in code, tests, tickets, and proposals. A concept missing from the glossary is either invented language or a real gap; raise the gap with the owner.
- If your work contradicts an ADR, say so explicitly, name the ADR, and say why it might be worth reopening.
